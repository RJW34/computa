## Scope (Holistic Process Targets)
The intended lifecycle is:
`Detect -> Preflight -> Transactional Apply -> Verify -> Compliance -> Commit/Rollback -> Launch/Use -> Supervise -> Diagnose -> Improve`

This overhaul implements:
1. Transaction engine with verification and critical auto-rollback.
2. Safe game-config ownership with invariants (protect controls/profile identity fields).
3. Unified capability graph with explicit blockers/warnings.
4. Watchdog + diagnostics bundle tooling.
5. Declarative manifests for linter/game-detection heuristics.
6. Release-facing integration test matrix scaffolding.

## Implementation Plan

### P1: Transaction + Compliance Engine
Deliverables:
- `abso/core/transaction.py`:
  - transaction phases/checkpoints
  - apply/verify/commit/rollback orchestration
  - backup-aware auto-rollback for critical verification failures
- `abso/core/compliance.py`:
  - compliance issue model (critical/warning/info)
  - policy that converts apply+verify outcomes into compliance report
- integration in `abso/main.py` `apply` command preserving existing JSON keys
- optional transaction metadata added to JSON output

Acceptance criteria:
- failed critical compliance with backup available triggers restore
- transaction checkpoints recorded in output/logs
- no regression for existing `apply` callers

### P2: Config Safety / Invariants
Deliverables:
- `abso/core/config_safety.py` safe patching utilities
- Rivals 2 config hardening in `abso/settings/rivals2_config.py`:
  - explicit allowlist of mutable keys
  - explicit protected-key invariants for identity/control fields
  - fail-safe behavior for unsupported key mutation attempts

Acceptance criteria:
- unknown keys are never applied silently
- protected fields cannot be clobbered by profile apply path

### P3: Unified Capability Graph
Deliverables:
- `abso/core/capabilities.py`
  - capability checks with blockers/warnings/info
  - profile-aware checks (VRR requirements, GPU/vendor checks, etc.)
- integrate into `ProfileApplier` preflight phase
- capability report surfaced in apply result

Acceptance criteria:
- blockers prevent unsafe apply
- warnings are surfaced without hard fail
- existing VRR prerequisite behavior remains deterministic

### P4: Watchdog + Diagnostics
Deliverables:
- `abso/core/health.py` diagnostics report + bundle writer
- CLI command(s) in `abso/main.py` for health/bundle generation
- tray supervision helpers in `abso/tray/__init__.py`:
  - detect tray process state
  - optional start-if-missing action

Acceptance criteria:
- one-shot health report and persistent bundle can be generated
- tray startup/health visibility is actionable

### P5: Declarative Heuristics
Deliverables:
- `abso/core/manifests/linter_rules.json`
- `abso/core/manifests/game_detection.json`
- loader utilities (`abso/core/manifests.py`)
- migrate linter + game detector constants to manifests with fallback defaults

Acceptance criteria:
- behavior parity with current defaults
- heuristics editable without code edits

### P6: Integration Test Matrix + CI
Deliverables:
- machine-readable matrix file (scenarios + expected outcomes)
- contract tests validating matrix structure/coverage
- CI workflow extension for matrix contract checks

Acceptance criteria:
- matrix schema enforced in tests
- CI fails when matrix contract breaks

### P7: Final Validation + Documentation
Deliverables:
- full test pass + lint/build checks
- update `CLAUDE_AGENT_HANDOFF_2026-02-18.md`
- update this file with final checkpoint statuses and stop-state notes

Acceptance criteria:
- all phases marked `COMPLETED` or explicit constrained partial
- repo history contains clear implementation narrative
